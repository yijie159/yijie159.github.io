# 点赞

需求：

- 同一个用户只能点赞一次，再次点击则取消点赞
- 如果当前用户已经点赞，则点赞按钮高亮显示(前端已实现，判断字段Blog类的isLike属性)

实现步骤：

1. 给blog类中添加一个isLike字段，标示是否被当前用户点赞
2. 修改点赞功能，利用Redis的set集合判断是否点赞过，未点赞过则点赞数+1，已点赞过则点赞数-1
3. 修改根据id查询blog业务，判断当前登录用户是否点赞过，赋值给isLike字段

BlogController.java

```java
	/**
     * 点赞
     * @param id
     * @return
     */
    @PutMapping("/like/{id}")
    public Result likeBlog(@PathVariable("id") Long id) {
        return blogService.likeBlog(id);
    }
```

BlogServiceImpl.java

```java
    @Override
    public Result queryHotBlog(Integer current) {
        // 根据用户查询
        Page<Blog> page = query()
                .orderByDesc("liked")
                .page(new Page<>(current, SystemConstants.MAX_PAGE_SIZE));
        // 获取当前页数据
        List<Blog> records = page.getRecords();
        // 查询用户
        records.forEach(blog -> {
            this.queryBlogUser(blog);
            this.isBlogLiked( blog);
        });
        return Result.ok(records);
    }

    /**
     * 查询博文详情
     * @param id
     * @return
     */
    @Override
    public Result queryBlogById(Long id) {
        // 1.查询blog
        Blog blog = getById(id);
        // 2.查询blog有关的用户
        queryBlogUser(blog);
        // 3.查询blog的点赞数量
        isBlogLiked(blog);
        return Result.ok(blog);
    }

    /**
     * 查询是否点赞
     * @param blog
     */
    private void isBlogLiked(Blog blog) {
        // 1.获取登录用户
        Long userId = UserHolder.getUser().getId();

        // 2.判断当前登录用户是否已经点赞
        String key = "blog:liked:" + blog.getId();
        Boolean isMember = stringRedisTemplate.opsForSet().isMember(key, userId.toString());
        blog.setIsLike(BooleanUtil.isTrue(isMember));
    }

    /**
     * 点赞
     * @param id
     * @return
     */
    @Override
    public Result likeBlog(Long id) {
        // 1.获取登录用户
        Long userId = UserHolder.getUser().getId();

        // 2.判断当前登录用户是否已经点赞
        String key = "blog:liked:" + id;
        Boolean isMember = stringRedisTemplate.opsForSet().isMember(key, userId.toString());
        if(BooleanUtil.isFalse(isMember)){
            // 3.如果未点赞，可以点赞
            // 3.1.数据库点赞数+1
            boolean isSuccess = update().setSql("liked = liked + 1").eq("id", id).update();
            // 3.2.保存用户到Redis的set集合
            if (isSuccess){
                stringRedisTemplate.opsForSet().add(key, userId.toString());
            }
        }else {
            // 4.如果已点赞，取消点赞
            // 4.1.数据库点赞数-1
            boolean isSuccess = update().setSql("liked = liked - 1").eq("id", id).update();
            // 4.2.把用户从Redis的set集合移除
            if (isSuccess){
                stringRedisTemplate.opsForSet().remove(key, userId.toString());
            }
        }
        return Result.ok();
    }

```

首先我们需要在Blog类当中添加一个`@TableField(exist = false)private Boolean isLike;`返回给前端以此来判断该用户是否存在点赞。

思路：

1. 获取登录用户
2. 通过获取redis缓存的数据判断当前登录用户是否点赞
   - 如果未点赞可以点赞
     - 数据库的点赞数量+1并且保存用户到redis的set集合当中，一个博客一个redis
   - 如果已经点赞，就取消点赞
     - 数据库的点赞数量-1并且把用户从Redis的set集合当中移除

以上是点赞的判断，因此查询热点博客和查询博文详情就需要查询是否存在点赞

# 点赞排行榜

在探店笔记的详情页面，应该把给该笔记点赞的人显示出来，比如最早点赞的top5，形成点赞排行榜![image-20260318171735697](/images/黑马点评/image-20260318171735697.png)

## 实现查询点赞排行榜的接口

需求：按照点赞时间先后排序，返回Top5的用户

|          | List                 | Set          | SortedSet       |
| -------- | -------------------- | ------------ | --------------- |
| 排序方式 | 按添加顺序排序       | 无法排序     | 根据score值排序 |
| 唯一性   | 不唯一               | 唯一         | 唯一            |
| 查找方式 | 按索引查找或首尾查找 | 根据元素查找 | 根据元素查找    |

BlogServiceImpl.java

```java
    /**
     * 点赞排行榜
     * @param id
     * @return
     */
    @Override
    public Result queryBlogLikes(Long id) {
        // 1.查询top5的点赞用户 zrange key 0 4
        String key = BLOG_LIKED_KEY + id;
        Set<String> top5 = stringRedisTemplate.opsForZSet().range(key, 0, 4);
        if (top5 == null || top5.isEmpty()){
            return Result.ok();
        }
        // 2.解析出用户id
        List<Long> ids = top5.stream().map(Long::parseLong).collect(Collectors.toList());
        String idStr = StrUtil.join(",", ids);

        // 3.根据用户id查询用户       WHERE id IN ( 1010 , 1) ORDER BY FIELD(id, 1010, 1)
        List<UserDTO> userDTOS = userService.query()
                .in("id", ids)
                .last("ORDER BY FIELD(id ,"+idStr+")")
                .list()
                .stream()
                .map(user -> BeanUtil.copyProperties(user, UserDTO.class))
                .collect(Collectors.toList());

        // 4.返回
        return Result.ok(userDTOS);
    }
```

由于`SortedSet`根据score值排序，因此查询top5的点赞用户可以使用`zrange`命令进行查询，如果不存在就直接返回空。

获取之后需要解析用id传给前端，因此需要把redis的set数据进行解析使用`top5.stream().map(Long::parseLong).collect(Collectors.toList());`转换成 List<Long>集合。

- `stream()`：将top5数据转换成字符串的集合：例如：["1", "5", "88", "102", "256"]
- `map(Long::parseLong)`：
  - 对流的每个元素应用转换操作
  - Long::parseLong 是方法引用，等价于 s -> Long.parseLong(s)
  - 将每个 String 类型的 ID 转换为 Long 类型，例如：["1", "5", "88"] → [1L, 5L, 88L]
- `collect(Collectors.toList())`：
  - 将转换后的流重新收集为 List 集合
  - 最终得到一个 List<Long> 类型的结果

在我们使用修改前的代码的时候，我们发现代码可以正常运行，但是点赞人数的显示却是新点赞的在前，旧的在后，这并不满足我们类似与微信朋友圈点赞的形式，而且我们的代码也并非错误的，这是因为mysql的缘故，在查询的时候使用的`WHERE id IN ( 1010 , 1)`实现的1010(先点赞)在前，1(后点赞)在后，成为了降序的步骤，因此我们需要对这个重新分组，因此使用`ORDER BY FIELD(id, 1010, 1)`限制排序顺序，使得可以正常显示，由于原本是直接使用ids，因此我们需要修改成sql语句重新设置in和拼接最后的语句。这里为了`1010, 1`也使用了`StrUtil.join(",", ids);`进行拼接。

然后由于我们这里的redis数据都使用的SortedSet，因此之前的一系列点赞操作也需要由set->SortedSet，使用score返回是否有值判断即可
